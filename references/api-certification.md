# Later: check and release your chosen API app

Use the website's current guide at
<https://developers.dezrez.com/reference/api/certification.md> after the person
has chosen and built their app. Resolve that path against the developer-site
origin actually in use if it differs. Do not add this workflow to the first
welcome or ask for release details before a feature has been chosen.

Keep the explicit `api:{version:'dezrez.api/1'}` declaration and empty old helper
permissions. Complete the actual owner, compatibility, activity, intended usage
and test declarations before submission. An API-only app does not need fake
private-note storage or property/note selectors. Preserve owner-approved
fictional partner details for an internal Systest demonstration; never invent
real contacts or usage. A minimal draft remains valid for local development.

Create the source-side `dezrez-certification.json` described by the website
guide. It defines successful fictional API exchanges, real visible UI controls,
the startup/action steps and an error indicator. Use correct endpoint contracts
and preserve full desired collections on replacement-style saves. The isolated
worker checks those exact compiled browser bytes and declared fictional
workflow without tokens, upstream network or actual business writes. It also
checks access failures, lifecycle, uncertain saves and protocol isolation.

Send the exact finished source through the normal website controls. Passing
checks is not approval or publication. The reviewer approves the exact evidence
and bytes; the publisher copies those bytes to the separate Systest app host.
Suspension and eligible rollback remain operator controls. Do not modify or
deploy the main Dezrez application as part of this workflow.
